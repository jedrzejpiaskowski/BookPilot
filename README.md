# BookPilot - Book Reading Planner

A modern React application for managing your reading plans and tracking reading progress.
Test it out [here](https://jedrzejpiaskowski.github.io/BookPilot).

## Overview

BookPilot is a personal book reading planner with a clean, intuitive interface. It helps you discover, organize, and track books with multiple dedicated sections:

- **Browse** - Search by title, author, or all fields with paginated results (9 books per page). Searches are deliberate (Enter or button) with cooldown protection. Result cards include save toggles and a details dialog with author info; covers and author photos are cached for faster repeat views.

- **Catalog** - Organize books into Saved, Wishlist, and Reading collections with drag-and-drop status changes. Includes compact cards for side lists and save timestamps for each entry.

- **Rate** - Track reading progress and rate books with a 10% increment slider and 5-star system. Lists auto-sort by progress then rating, with distinct styling for 4- and 5-star titles and a completion toast at 100%.

- **Home** - Shows quick reading statistics like totals, reading status counts, completed books, and average rating for completed titles.

**Design & UX:**
- Elegant serif typography (Playfair Display for headers, Lora for body text) with a warm beige background resembling aged paper
- Light theme by default with a user-toggleable dark mode (dark gray with subtle brown tones and beige typography) via the header icon
- Responsive layout that adapts to mobile, tablet, and desktop screens
- Smooth transitions and animations for page reordering when books are rated or progress changes
- Toast notifications with Material-UI Snackbar for user actions (save, remove, completion)
- Navigation includes book count badges for Catalog and Rate

All data is stored locally in your browser using IndexedDB, ensuring privacy and offline accessibility.

## My insights

Note: Almost all of the prompts that I used can be bound in [prompt-log.md](docs/prompts/prompt-log.md) file.
I only removed short clarifying prompts like *Yes/No*, after restoring some changes I did not like or when I changed approach.

### 📝 General Approach

Approached Copilot as if starting a new project solo:
  - Outlined a high-level plan first.
  - Broke tasks into smaller, manageable steps.
- After each code generation, I performed mini code reviews:
  - Reviewed the generated code carefully.
  - Added corrective prompts when needed — this approach worked well.
  
Tested Copilot with ambitious or slightly oversized tasks:
- Mostly handled them well.
- Eventually found a good prompt rhythm: concise, yet producing the desired results.

###  Observations
- Copilot was surprisingly useful even at the planning stage:
  - Generated a sensible implementation plan that I mostly followed.
- Generating initial code chunks was very easy:
  - Most code was error-free.
  - Minor issues were often caught and fixed during reasoning.
- Nearly all code was generated by the agent:
  - Only minor edits required (styling, literals, phrasing).
- Impressive contextual awareness:
  - For example, changing one button’s behavior prompted Copilot to adjust a similar button automatically without me asking for it.
- Now that I am aware of more prompting techniques after going through provided materials I am sure I would use Copilot even more effectively by:
  - using @ to call specific assistants
  - changing between Agent/Ask more frequently to get more tailored results
  - defining more copilot instructions
  - using more prompting techniques
  
  Yet still my level of knowledge allowed me to use this tool in a very effective way.

###  Performance and Usability
- No major differences noticed between models (but I was not trying specifically to find differences):
  - Mostly used premium models (auto-selection) or Claude Haiku 4.5 for cost-efficiency.
  - x0-multiplier models worked fine too for shorter or simple tasks.
- I attribute good results attributed to prompt-writing skills and understanding model strengths.
- Premium request pacing is reasonable:
  - Auto-selection allows implementing a large amount of functionality efficiently.
- Excellent for generating new code quickly:
  - Editing, refactoring, or precise adjustments I assume would be less spectacular but still helpful.

### Challenges and Limitations
- Following specific instructions was sometimes tricky:
  - Logging all prompts to a file required trial and error.
  - Issues included stopping logging, wrong date formats, or problems after switching models/devices, starting new session
  - reasoning tends to be slower/less performat if no context is given even for seemingly simple tasks
- Implementation edge cases:
  - Some improvements are hard to express directly in code (e.g., styling issues like black button on white background).
  - Highlighting suspected errors or providing screenshots was helpful in a few cases.

### Summary
- Copilot and AI agents significantly speed up code generation.
- Contextual understanding can catch implicit issues.
- Manual oversight is still needed for precision work and cross-device consistency.
- Overall, Copilot is a major productivity boost and very helpful for high-level implementation tasks.
